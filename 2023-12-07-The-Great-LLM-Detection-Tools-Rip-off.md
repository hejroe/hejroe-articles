There are a number of organisations that are offering tools/services that claim to be able to detect AI generated content. I think it is important to prove just how fallacious those claims are. Of course, this is not the only industry segment that makes grand statements relating to artificial intelligence as there are many others.

There are a number of organisations that are offering tools/services that claim to be able to detect AI generated content. I think it is important to prove just how fallacious those claims are. 

Of course, this is not the only industry segment that makes grand statements relating to artificial intelligence as there are many others. But it is perhaps one of the easiest to dispute in a simple scientific method. So as much as I am picking quite specifically on AI detection, many of the same principles can be applied to other industries. 

Firstly, it is necessary to frame exactly what is being disproved. This is pretty easy given the broad ranging capabilities that AI detection tooling claim. In the simplest of terms, the creators of such tools state that they can detect content generated by a Large Language Model (LLM) or similar AI methods. Now for the loose and easy science in disproving such claims. 

## The Simplest of Prompts 

"Create a simple 'hello world' program in Python" is the writing prompt given to the most commonly used and high profile LLMs that are publicly available. There are many others that can be used. Specifically they were, in alphabetical order, Bard from Google, 

Bing from Microsoft and Chat-GPT from Open-AI. The response to the writing prompt are as follows: 

Bard - print("Hello, World!") 

Bing - print('Hello World') 

Chat-GPT - print("Hello, World!") 

The writing prompt was very deliberately chosen as it is commonly used as the first program to be taught to more human programmers. It shows the use of a function as well as an output stream, two core concepts that are built on. 

As a human, my go to "hello World" program could be anyone of these depending on the reference material I am using and the mood I am in. If I were to then ask any of the AI detection tools to state if it was human or AI generated what would the response be? I mean I have just used the same prompt for three different LLM implementations which have all answered the request correctly. So the presented evidence is that they are all created by AI. 

But any tool or service that would claim to be able to tell you if it was human or AI generated would simply be guessing at best. The more honest implementations would describe it as being "undetermined" or similar. The reason for this is that there are only so many ways that this program can be written. Many of which are considered obvious and simple.

## Adding Complexity 

There are some who may, and rightly so, scorn the idea of the utility of such a simple program with the "hello world" example. They are both right and wrong in this. They are right as who would use such a program in the real world and what problem does it solve? But they would be wrong in that the problem it actually solves is a learning one and not a directly productive output one. 

If we were to take the simple program so far and add complexity, we again get similar results. I would suggest that adding graphical user interface (GUI) element is a reasonable next step up. The writing prompt for this would be "Create a simple 'hello world' program in Python that uses a GUI.". The results being: 

Bard - 
``` code
import tkinter as tk 

# Create the main window 
window = tk.Tk() 
window.title("Hello World") 

# Create a label widget 
label = tk.Label(window, text="Hello World") 

# Pack the label widget 
label.pack() 
# Start the main loop 
window.mainloop() 
```

Bing - 
``` code
import tkinter as tk 

root = tk.Tk() 
root.title("Hello World") 

label = tk.Label(root, text="Hello World") 
label.pack() 

root.mainloop() 
```

Chat-GPT - 
``` code
import tkinter as tk 

# Create a new Tkinter window 
window = tk.Tk() 

# Set the title of the window 
window.title("Hello, World!") 

# Create a label widget with the "Hello, World!" message 
label = tk.Label(window, text="Hello, World!") 

# Pack the label widget to add it to the window 
label.pack() 

# Start the Tkinter event loop 
window.mainloop() 
```

There is again little difference in the output from each of the LLMs. Yet the complexity, from a system level, is greatly increased. 

What about if we were to also write the output to a file? Not wishing to be inefficient and to also allow for a bit of freedom in interpretation the prompt "also write the output to a file" was used. 

Bard - 
``` code
import tkinter as tk 

# Create the main window 
window = tk.Tk() window.title("Hello World") 

# Create a label widget 
label = tk.Label(window, text="Hello World") 

# Pack the label widget 
label.pack() 

# Write the output to a file 
with open('hello_world.txt', 'w') as f: 
    f.write('Hello World\n') 

# Start the main loop 
window.mainloop() 
```

Bing - 
``` code
import tkinter as tk 

root = tk.Tk() 
root.title("Hello World") 

label = tk.Label(root, text="Hello World") 
label.pack() 

with open('output.txt', 'w') as file:

root.mainloop() 
```

Chat-GPT - 
``` code
import tkinter as tk 

# Create a new Tkinter window 
window = tk.Tk() 

# Set the title of the window 
window.title("Hello, World!") 

# Create a label widget with the "Hello, World!" message 
label = tk.Label(window, text="Hello, World!") 

# Pack the label widget to add it to the window 
label.pack() 

# Write the "Hello, World!" message to a file 
with open("output.txt", "w") as file: 
    file.write("Hello, World!") 

# Start the Tkinter event loop 
window.mainloop() 
```

With this simple example we now have a plethora of programming functions being performed, all leading to very similar output and result. Those inclined to be more efficient may have wanted to use a mechanism that allowed for the output message to declared once as a variable. But the answers offered are not wrong. 

## The Source of Creativity 

In the examples offered so far there is not a great deal of creativity. It is however the basis for creativity, at least in my opinion. With the code stubs produced we could easily compare them to numbers or letters of the alphabet, musical notes or even colours and textures. On their own they are quite simple and dull. But once you start to add them to each other you can get impressive results. Artistic even. 

In this we again hit a wall of understanding when it comes to a definition of creativity. A variety of dictionary definitions will offer things relating to imagination and ideas to create something new. As normal things start to prove elusive in trying to be exact. 

What if we were to ask the LLMs to produce some code where the test to be displayed is to be 10 thousand words on the theme of the colour purple? The LLMs would respond with something. The content would not be random as it was prompted by a theme of a colour. It would likely be unique. The ideas and imagination are required to link the 10 thousand words to the colour purple in this instance. Does this mean this is a creative work? Hold any thoughts you may have on that as we are not done with this topic yet. 

## Brute Force and Creativity 

Programming is only one dimension of creative human endeavour, as I consider "good programming" to be akin to an art. Programming is not the only discipline where human creativity is present. Consider music, where there are but 12 notes. How we can mix these notes up, combine them and a multitude of other aspects that can be altered gives a massive amount of possible permutations. But anyone who has studied any form of music theory can tell you that there seem to be patterns that are more popular than others. Also, certain characteristics seem more prevalent than others. For instance, 120 beats per minute is a very common timing for music that many find agreeable. The pentatonic scale is one that humans seem to have as a built-in feature, just ask Bobby McFerrin. 

As computing power has increased so has our ability to map out immense numbers of possible permutations. The work of Noah Rubin and Damien Riehl even went so far as to make available every possible combination of 8-note, 12-beat melodies. Details of their project, including source code and output downloads, can be found at [http://allthemusic.info/](http://allthemusic.info/).

In this novel piece of work we see rule-based creativity. This is not imagination or ideas outside of the sense of the initial conditions for creating the auto-generated works. Given that the requirements for copyright ownership is that there is a human author and that the material is "recorded" in some manner then it meets both. It is easy to argue that many of the recorded pieces are simply auditory junk. But unfortunately this is a subjective opinion that the top 100 of any country or genre of music will test to the limits. 

## The Essence of the Problem 

All of this brings us to a point that I hope I can wrap up. The production of the AI detection tools is to combat a very human problem. This is best described as a human(s) looking to maximise reward for minimum effort. In all cases it is looking to prevent theft of some kind. Theft of creative works or intellectual plagiarism. The unlicensed use of work or passing it off as your own effort. In doing so such tools are exasperating the problem by offering hope to clients, harassment to the accused and profits for themselves. 

Rather than actually address a more pressing issue of creativity, ideas, effort and reward we are left with an untested and uncomfortable mix of the new clashing with the old. 

It is likely prudent to consider how much of the intellectual property law came into being. Who owns what for how long and all the other issues that can relate to ownership has been hotly contested since, well since things could be owned. Arguably the basis of all law is founded on such principles. Do you own yourself and do you have any rights for instance? Still a contested subject for some in this modern day and age. 

## The Real Problem 

At this moment in our history, we are at a point where production of certain things is incredibly simple and cost efficient. Artificial intelligence is only exasperating this issue more. I could, if I wanted, just simply writing hundreds of thousands of words everyday by prompting various AIs in all their guises. Would it make sense or any of it be any good? In all honesty probably some of it would at the very least seem convincing. 

Already we are seeing numerous channels that are able to create shows/news at an incredible rate. Faster than a single human could consume it. Tool chains are being created that would allow you to take a photograph, write an essay on the photograph, use the essay to produce a musical, turn the musical into a complete film all with AI. This is the reality that we are heading to. There is no easy solution to just turn this all off via legislation. By the time the new laws are written the technologies that are supposed to be policed will be superseded by orders of magnitude. 

In closing, AI is wonderful stuff in many respects. But there are many that are interested in extracting your hard-earned money on promises that cannot be held. If your business model is to be reliant on a drawing from some guy who died 90 odd years ago being similar to the drawing of another mouse, then the next few years are going to be tough. But if that is your business model you may be hopeful of the promises offered by AI detection tools.
